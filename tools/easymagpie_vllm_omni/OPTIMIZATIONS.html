EasyMagpie vLLM-Omni: validated optimization inventory

This inventory describes the selected implementation measured on 14 October 2026: source-admission-lookahead-variant. It combines the earlier native code-predictor changes with the selected SGLang-inspired scheduling, input preparation, feedback and FP32 codec changes. The four-decode admission policy is a vLLM experiment; it is not an exact copy of SGLang's scheduler.

The selected implementation exceeded the historical SGLang throughput reference at C64 and C128. TTFA still trails SGLang, and C128 still has frequent playback underruns. The measured results apply to the complete configuration below. They do not assign a speedup to every individual feature.

Use the README, optimized launcher and H100 capacity-128 profile for deployment. The runtime patch installer checks the supported upstream files against the runtime manifest.

Changes applied

Every row below is part of the selected implementation. Feature flags are opt-in; all 21 flags listed in the table are enabled by the optimized launcher. The local-transformer changes apply directly to its implementation.

Selected configuration

Hardware and concurrencyOne standalone H100 80 GB; MPS enabled with active thread percentage 100. Talker and codec each allow 128 active sequences. Client concurrency is 64 or 128; it is distinct from active capacity and from the codec's warmed graph batch sizes.
Model and precisionLocal NIM 170k export, voice eng. FP16 talker with deliberate FP32 parameters, FP32 Mamba state and FP32 codec. cuDNN TF32 enabled; CUDA matmul TF32 disabled. FP32 tensor dtype does not mean cuDNN TF32 is disabled.
Streaming chunks2 frames, then 6 frames, then 8-frame steady chunks; 1,764 samples/frame at 22,050 Hz. Speech delay 5, phoneme delay 3, text prefill 4. Cold voice conditioning produces 71 prefill tokens.
Talker allocation4 GiB KV budget; max model length 4,096; max batched tokens 4,096; async scheduling and chunked prefill enabled, prefix caching disabled.
Codec allocation256 MiB state budget; max model length and batched tokens 4,104; async scheduling enabled, chunked prefill and prefix caching disabled. The outer stage remains eager while the plugin replays its explicit codec graphs.
Graph coverageMamba cold-prefill islands: 14 layers × batches 1–8 = 112 entries. Codec: batches 1–64 × frame counts 2/6/8 = 192 entries. The talker compilation profile separately includes decode buckets through 128 and larger token-count buckets through 4,096.
Measured softwarevLLM 0.26, vLLM-Omni 0.26, PyTorch 2.11.0+cu130 and Triton 3.6. The runtime patch is bound to exact upstream source hashes; a version label alone is insufficient.
Benchmark workloadInflight replenishment; 128 corpus entries requested 32 times each = 4,096 requests/round. Same model hashes, corpus, client, chunk schedule and CPU affinity across the compared runs. Server affinity: 0,24,1,25,2,26,3,27,4,28,5,29,6,30,7,31; client: 8,32,9,33,10,34,11,35. These CPU numbers are host-specific.

Retained branch behavior

The branch already had the native stateful two-stage codec, GPU-resident feedback keys, omission of backbone hidden states from the inter-stage payload, speaker/assembled-prefill caching, full-text tokenization once per request, async talker scheduling, compiled code prediction, streaming lifecycle handling, packed codec state kernels, and an FP32 codec default. Those are part of the serving path but are not new optimizations in this port. The new work extends their batching, ownership and graph execution; it does not replace the tokenizer or add a new HTTP API.

All rows have zero request errors. C64 vLLM RTFx is the median of 324.65× and 333.79×; its TTFA values pool the 8,192 raw responses. Other rows are one round each. The final C128 round followed an extra 4,096-request C128 workload on the same server; that workload is excluded from its metrics. Diagnostic cohorts and two standard warmup batches were excluded from every measured round.

RTFx is total emitted audio duration divided by measured wall time. TTFA is client-observed time to first audio, with inclusive percentile interpolation. Playback starts at first PCM with no extra reserve; an underrun counts a later interval in which the playback buffer empties before more audio arrives. It is not a packet-loss count. The final C128 maximum buffer deficit was 123.495 ms.

The longer C128 warmup did not improve throughput or TTFA in this repeat. C64 throughput is 13.1% above its historical SGLang reference; warmed C128 throughput is 4.3% above its reference. TTFA remains substantially larger. These historical comparisons are not interleaved trials and provide no variance estimate. Successful request completion and two exact diagnostic transcriptions in the latest C128 run do not establish full audio-quality equivalence.

Experiments excluded from this selection

  • Whole-backbone prefill graphs: a validated alternative, but slower in the retained serving trial than the selected Mamba islands.
  • Three-decode admission window: measured below the selected four-schedule window.
  • Pinned codec-group indices and a blocking payload-completion event: validated alternatives whose single serving trials did not establish an improvement over the selected source.
  • Compiled SGLang codec and its fused history adapter: not served. Retained-cache checks passed, but the fresh-cache run failed a warm-history numerical tolerance; the gate was not relaxed.
  • Channels-last codec weights: failed the retained PCM numerical acceptance checks.
  • Tmpfs stage transport: the serving trial missed required lifecycle close receipts and did not improve throughput.
  • Codec coalescing delay, sender-priority variants and diagnostic instrumentation: not enabled in this profile.
